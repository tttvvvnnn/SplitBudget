# Family Expenses Bot

Telegram-бот для учёта семейных трат с mini app: добавляйте траты (название, сумма, фото чека,
дата), выбирайте, кто из участников чата должен скинуться (поровну или произвольными суммами),
смотрите баланс и кто кому должен, гасите долги, ведите повторяющиеся траты (аренда, подписки),
смотрите статистику по категориям и выгружайте отчёт в Excel.

Стек: Python (aiogram 3 + FastAPI + SQLAlchemy/SQLite), фронтенд mini app — обычный HTML/CSS/JS
без сборки, использует официальный Telegram Web App SDK.

## Как это устроено

Один Docker-контейнер, один процесс: FastAPI поднимает REST API (`/api/...`), отдаёт статику
mini app (`/`) и параллельно (в фоне, тем же event loop) крутит long-polling Telegram-бота.
База — файл SQLite на диске (том `./data/db`), фото чеков — там же на диске (том `./data/photos`).

Важный технический момент: Telegram Bot API **не даёт** ботам получить список участников группы
напрямую — это ограничение платформы, а не этого проекта. Поэтому бот запоминает участника, как
только тот: (а) написал любое сообщение в группу, (б) был добавлен в группу через "Add members",
либо (в) впервые открыл mini app (тогда бэкенд дополнительно проверяет его членство напрямую через
Telegram API). На практике: после добавления бота в чат попросите всех участников написать в чат
хотя бы одно сообщение (или просто открыть приложение) — после этого они появятся в списке.

## Шаг 1. Создать бота через @BotFather

1. Откройте в Telegram чат с [@BotFather](https://t.me/BotFather).
2. `/newbot` → задайте имя и юзернейм (должен заканчиваться на `bot`).
3. BotFather пришлёт токен вида `123456789:AA...` — это ваш `BOT_TOKEN`.
4. (Рекомендуется) `/setprivacy` → выберите бота → **Disable**. Это позволит боту видеть все
   сообщения в группе (а не только команды), что нужно для отслеживания участников.
5. (Опционально, но удобно) `/setmenubutton` → выберите бота → в качестве URL укажите ваш будущий
   адрес mini app (например `https://expenses.example.com`) → название кнопки, например «Траты».
   Это добавит кнопку-меню в личном чате с ботом.

Бот получает доступ к mini app автоматически через кнопки с `web_app` в чате — отдельно
регистрировать mini app в BotFather не обязательно, если вы используете кнопки из группы
(как сделано в этом проекте: команды `/start` и `/app` в группе присылают кнопку «Открыть учёт трат»).

## Шаг 2. Подготовить сервер

Нужен VPS с Docker и Docker Compose, домен (поддомен), направленный на сервер, и HTTPS-сертификат —
Telegram обязательно требует HTTPS для mini app, самоподписанный сертификат не подойдёт.

```bash
git clone <этот репозиторий> family-expenses-bot
cd family-expenses-bot
cp .env.example .env
```

Заполните `.env`:

```
BOT_TOKEN=<токен от BotFather>
WEBAPP_URL=https://expenses.example.com   # ваш домен, без / на конце
DEFAULT_CURRENCY=RUB
SCHEDULER_TIMEZONE=Europe/Moscow
```

## Шаг 3. HTTPS и реверс-прокси

Приложение слушает `127.0.0.1:8000` внутри контейнера — наружу его отдаёт ваш существующий
nginx/Caddy с TLS. Пример конфига — `nginx/family-expenses-bot.conf.sample`:

```bash
cp nginx/family-expenses-bot.conf.sample /etc/nginx/sites-available/expenses.example.com.conf
# поправить домен внутри файла
ln -s /etc/nginx/sites-available/expenses.example.com.conf /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
certbot --nginx -d expenses.example.com
```

Если у вас Caddy — там HTTPS настраивается автоматически, достаточно:

```
expenses.example.com {
    reverse_proxy 127.0.0.1:8000
}
```

## Шаг 4. Запуск

Вручную (сборка прямо на сервере):

```bash
docker compose up -d --build
docker compose logs -f
```

Либо настройте автодеплой: пушите в GitHub → Actions сам соберёт образ и обновит сервер по SSH.
Пошаговая настройка — в [`DEPLOYMENT.md`](./DEPLOYMENT.md).

При старте бот сам снимает вебхук и переходит в режим polling, применяет миграции БД
(`alembic upgrade head` — см. `migrations/`), запускает планировщик повторяющихся трат
(проверка каждый день в 09:00 по `SCHEDULER_TIMEZONE`). Проверить, какая версия сейчас
задеплоена: `curl https://ваш-домен/healthz`.

## Шаг 5. Добавить бота в семейный чат

1. Создайте групповой чат в Telegram (или используйте существующий), добавьте туда бота.
2. Напишите в чате `/start` — бот поздоровается и пришлёт кнопку **«💸 Открыть учёт трат»**.
3. Попросите всех членов семьи написать в чат любое сообщение — так бот узнает о них
   (см. пояснение выше про ограничение Telegram Bot API).
4. Дальше приложение открывается кнопкой из `/start` или командой `/app` в любой момент.

## Функционал mini app

- **Траты** — список за месяц (свайп месяцев стрелками), добавление новой траты: название,
  сумма, категория, дата, фото чека (камера/галерея), кто оплатил, как делить — поровну между
  выбранными участниками или вручную (фиксированная сумма на каждого). Редактирование и удаление
  своих и чужих трат. Экспорт месяца в Excel (два листа: траты и баланс).
- **Баланс** — упрощённый список «кто кому должен» (минимальное число переводов) + баланс
  каждого участника + кнопка «Погасить» для фиксации перевода вручную + история платежей.
- **Статистика** — сумма и разбивка по категориям за месяц с диаграммой.
- **Повторы** — шаблоны повторяющихся трат (аренда, подписки): раз в месяц в указанный день
  автоматически создаётся трата и приходит уведомление в чат.

При добавлении новой траты и при погашении долга бот присылает уведомление в групповой чат.

## Локальная разработка / тестирование

Telegram требует HTTPS даже для тестирования mini app, поэтому локально проще всего пробросить
порт наружу через туннель, например [ngrok](https://ngrok.com) или Cloudflare Tunnel:

```bash
pip install -r requirements.txt
cp .env.example .env   # заполнить BOT_TOKEN
uvicorn app.main:app --reload --port 8000
# в другом терминале:
ngrok http 8000
```

Полученный `https://xxxx.ngrok-free.app` укажите как `WEBAPP_URL` в `.env` и перезапустите —
теперь можно открывать приложение из тестового бота.

### Автотесты

```bash
pip install -r requirements-dev.txt
pytest -v
```

Тесты поднимают приложение целиком (миграции, роутеры) во временной SQLite-базе и проверяют
бизнес-логику через HTTP-API: сплиты (поровну/вручную, округление копеек), расчёт баланса и
погашение долгов, генерацию и идемпотентность повторяющихся трат, аутентификацию по initData,
загрузку/отдачу фото, экспорт и статистику. Тот же набор гоняется в CI на каждый пуш/PR
(`.github/workflows/ci.yml`) и повторно перед сборкой релиза (`release.yml`).

## Релизы и деплой

Версии — по [SemVer](https://semver.org/lang/ru/) (`v1.2.0`), меняются через git-теги, а не на
каждый пуш в `main` — так версия на сервере всегда соответствует конкретному релизу и записи в
`CHANGELOG.md`. Как выпустить релиз — в [`RELEASING.md`](./RELEASING.md), как настроить сам
автодеплой на сервер (GitHub Actions → ghcr.io → SSH) — в [`DEPLOYMENT.md`](./DEPLOYMENT.md).

## Структура проекта

```
app/
  main.py              # точка входа: FastAPI + бот + планировщик в одном процессе
  bot/                 # aiogram: команды, отслеживание участников, уведомления, планировщик
  api/                 # FastAPI: аутентификация initData, роутеры REST API
  shared/               # общие модели SQLAlchemy, схемы Pydantic, расчёт баланса, миграции
migrations/            # схема БД версионируется через Alembic (alembic upgrade head при старте)
tests/                 # pytest — бизнес-логика поверх HTTP API
webapp/                # mini app: index.html + css/js, без сборки
data/                  # база SQLite и фото чеков (volume, не коммитить)
nginx/                 # пример конфига реверс-прокси
.github/workflows/     # CI (тесты) + Release (сборка образа, релиз на GitHub, деплой по SSH)
docker-compose.prod.yml # продовый compose, тянет готовый образ из ghcr.io (для автодеплоя)
CHANGELOG.md            # Keep a Changelog — что вошло в каждую версию
RELEASING.md            # как выпустить релиз: версии, теги, миграции, хотфиксы
DEPLOYMENT.md           # как настроить автодеплой на сервер
```

## Известные ограничения / что можно улучшить дальше

- Участник должен хотя бы раз написать в группу или открыть приложение, чтобы бот его увидел —
  так работает Telegram Bot API, полный список участников боту недоступен.
- Валюта одна на чат (задаётся `DEFAULT_CURRENCY`, отдельного экрана смены валюты в mini app нет).
- Категории — фиксированный список в `app/shared/config.py` (легко расширить).
- Фото хранятся на диске контейнера как файлы — для бэкапа не забывайте копировать `./data/photos`
  вместе с `./data/db`.
